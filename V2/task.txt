1. Save Data Functionality
- Add a "Save Data" button on the Data tab.

- The existing JSON file located in the /data directory should be automatically updated/replaced with the latest data.
- Include success and error notifications after save operations.
- Validate data before saving to prevent corrupt JSON.

2. Daily History Improvements
- Fix the Daily History table column mapping issue.
- Currently the headers do not align with the displayed data. Ensure each column displays the correct field:
  - Date → Date
  - Remaining SP → Remaining Story Points
  - Features Left → Features Remaining
  - PBIs Done → Completed PBIs
  - Notes → Notes
  - Sprint → Sprint Number
- Make every Daily History row fully editable.
- Users should be able to add, edit, and delete Daily History entries directly from the UI.
- Changes should be included when Save Data is clicked.

3. Daily Sprint Update Enhancements
- Add a Sprint selection dropdown to the Daily Sprint Update section.
- The dropdown should automatically default to the currently active sprint.
- Users must be able to switch to any sprint and add/update daily progress information for that sprint.
- Newly entered updates should automatically appear in the Daily History table.

4. Overall Features Burndown (All Sprints)
- Add a new "Overall Features Burndown" chart under the Overall / All Sprints section.
- This chart must show release-level progress across all sprints instead of individual sprint progress.
- Example:
  - Total release features = 43
  - Sprint 1 completed features = X
  - Sprint 2 completed features = Y
  - Sprint 3 completed features = Z
  - Remaining features should decrease accordingly.
- The chart should display:
  - Planned burndown line
  - Actual burndown line
  - Remaining features trend
- Support approximately 6–7 sprints per release.

5. Release-Level Planning Data
- Add a dedicated Release Planning / Release Metrics section (preferred over the existing History section).
- Allow users to define:
  - Release Name (e.g., V-1.3)
  - Total Features Planned
  - Number of Sprints
  - Features Completed Per Sprint
  - Remaining Features
- This data will feed the Overall Features Burndown chart.
- The dashboard should automatically recalculate remaining features whenever sprint completion data changes.

6. General Requirements
- Preserve all existing functionality.
- Ensure all new fields are loaded from and saved back to the JSON file.
- Maintain responsive UI design.
- Ensure charts refresh immediately after data changes or save operations.
